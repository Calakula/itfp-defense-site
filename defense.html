Қорғаудағы сұрақтарВопросы на защитеDefense Q&A

Ықтимал сұрақтар мен қысқа жауаптар және «тірі модификация» (15 балл) идеялары.Вероятные вопросы с короткими ответами и идеи для «живой модификации» (15 баллов).Likely questions with short answers and ideas for the “live modification” (15 points).

Таза функция деген не және сенде қайда бар?Что такое чистая функция и где она у вас?What is a pure function and where do you have one?
Жанама әсері жоқ: бірдей кіріс → бірдей шығыс, консоль/файл/global күйді оқымайды. Мысалдар: PricingPolicies.Price, OrderWorkflow.Quote/Confirm, Reports.DispatchList, Assigner.Plan. I/O тек DataLoader, ReportExporter, Program-да.
Функция без побочных эффектов: тот же вход → тот же выход, не читает консоль/файлы/глобальное состояние. Примеры: PricingPolicies.Price, OrderWorkflow.Quote/Confirm, Reports.DispatchList, Assigner.Plan. Ввод-вывод только в DataLoader, ReportExporter, Program.
No side effects: same input → same output, no console/file/global state. Examples: PricingPolicies.Price, OrderWorkflow.Quote/Confirm, Reports.DispatchList, Assigner.Plan. I/O only in DataLoader, ReportExporter, Program.
Неге DeliveryRequest — record емес, class?Почему DeliveryRequest — class, а не record?Why is DeliveryRequest a class, not a record?
record-тың жария with-і бар, ол Create фабрикасын айналып өтіп өрістерді қоя алады. Жеке конструкторлы және setter-сіз class әр данасы тексеруден өткенін кепілдейді (№1 ақау).
У record есть публичный with, который копирует и позволяет задать поля в обход фабрики Create. Class с приватным конструктором и без сеттеров гарантирует: каждый экземпляр прошёл проверку (дефект №1, тест NoUncheckedConstruction_...).
A record has a public with that copies and sets fields bypassing the Create factory. A class with a private constructor and no setters guarantees every instance was validated (defect #1, test NoUncheckedConstruction_...).
Map мен Bind айырмасы қандай? Көрсет.Чем Map отличается от Bind? Покажи.How does Map differ from Bind? Show it.
Map: T → U (құлай алмайды), нәтиже Success-ке оралады. Bind: T → Result<U> (құлай алады), нәтиже өзгеріссіз алынады. OrderService.Process-те: құлауы мүмкін қадамдар Bind-пен, соңындағы таза түрлендіру Map-пен.
Map: T → U (функция не может упасть), результат оборачивается в Success. Bind: T → Result<U> (функция может упасть), результат берётся как есть. В OrderService.Process: FindOrder.Bind(QuoteStep).Bind(ConfirmStep).Map(ToView) — шаги, которые могут отказать, через Bind; чистое преобразование в конце — через Map.
Map: T → U (cannot fail), result wrapped in Success. Bind: T → Result<U> (can fail), result kept as is. In OrderService.Process: FindOrder.Bind(QuoteStep).Bind(ConfirmStep).Map(ToView) — fallible steps use Bind; the pure conversion at the end uses Map.
Операциялардың дұрыс емес реттілігі қалай болдырылмайды?Как у вас предотвращён неверный порядок операций?How is an invalid operation order prevented?
Күйлер — әртүрлі типтер; Submitted-те баға жоқ, сондықтан оған Confirm Refused(InvalidState) қайтарады. OrderBook өзгермейді: бас тартқанда сол кітап қайтады. Заңды реттілік (қайта растау) рұқсат етіліп, идемпотентті қалады.
Состояния — разные типы (Submitted, Quoted, Confirmed); у Submitted нет цены, поэтому Confirm на нём возвращает Refused(InvalidState). OrderBook неизменяема: при отказе возвращается та же книга. Легальный порядок (повторное подтверждение) остаётся допустимым и идемпотентным.
States are distinct types (Submitted, Quoted, Confirmed); Submitted has no price, so Confirm on it returns Refused(InvalidState). OrderBook is immutable: on refusal the same book is returned. A legitimate order (repeated confirmation) stays allowed and idempotent.
Higher-order функция қайда және ол нені өзгертеді?Где higher-order function и что она меняет?Where is the higher-order function and what does it change?
PriceRequests(eligible, Func<...> policy) — standard немесе express бағаны өзгертеді. Сонымен қатар Assigner.Plan(..., policy), PricingPolicies.WithDiscount, Scoring.CreateScore.
PriceRequests(eligible, Func<DeliveryRequest, decimal> policy) — standard или express меняют цену. Ещё: Assigner.Plan(..., policy) (FirstFit/BestFit), PricingPolicies.WithDiscount (принимает и возвращает функцию), Scoring.CreateScore.
PriceRequests(eligible, Func<DeliveryRequest, decimal> policy) — standard or express changes the price. Also Assigner.Plan(..., policy) (FirstFit/BestFit), PricingPolicies.WithDiscount (takes and returns a function), Scoring.CreateScore.
Мұндағы каррирлеу және жартылай қолдану не?Что такое каррирование и частичное применение у вас?What are currying and partial application here?
WeightedScore Curry()-мен dw → ww → request → score болады. curried(dw)(ww) екі аргументті бекітеді. DistanceFirst және HeavyFirst — екі жартылай қолданылған функция.
WeightedScore(dw, ww, request) каррируется Curry() в dw → ww → request → score. curried(dw)(ww) фиксирует два аргумента — получается Func<DeliveryRequest, decimal>. DistanceFirst (2; 0,5) и HeavyFirst (0,5; 2) — две частично применённые функции.
WeightedScore(dw, ww, request) is curried by Curry() into dw → ww → request → score. curried(dw)(ww) fixes two arguments, giving Func<DeliveryRequest, decimal>. DistanceFirst (2; 0.5) and HeavyFirst (0.5; 2) are two partially applied functions.
Deferred execution дегеніміз не және қайда материализациялайсың?Что такое deferred execution и где вы материализуете?What is deferred execution and where do you materialise?
LINQ/yield return санағанға дейін ештеңе есептемейді. QuoteStream.PriceLines есептеусіз жасалады. Материализация — Reports.DispatchList-те бір рет саналы түрде (ToImmutableArray).
LINQ/yield return не вычисляет до перечисления. QuoteStream.PriceLines создаётся без вычислений (тест это проверяет). Материализация — осознанно один раз в Reports.DispatchList (ToImmutableArray), чтобы получить стабильный снимок и не пересчитывать цену при повторном обходе.
LINQ/yield return computes nothing until enumerated. QuoteStream.PriceLines is created without computing (a test checks it). Materialisation is deliberate and once, in Reports.DispatchList (ToImmutableArray), for a stable snapshot without repeated pricing.
Null бола тұра неге Option? Неге Some(0)?Зачем Option, если есть null? Почему Some(0)?Why Option instead of null? Why Some(0)?
null — тексеруді ұмытуға болатын жасырын қате. Option жоқтықты типке айналдырады. 0 % жеңілдік жазбасы — табылған жазба (Some(0)), жазба жоқ — None.
null — скрытый отказ, который легко забыть проверить. Option делает отсутствие типом. Запись о скидке 0 % — это найденная запись (Some(0)), а отсутствие записи — None; их нельзя путать.
null is a hidden failure that is easy to forget to check. Option makes absence a type. A 0 % discount record is a found record (Some(0)), a missing record is None; they must not be confused.
Қандай exception-дарды ұстайсың және неге дәл сол?Какие исключения вы ловите и почему именно их?Which exceptions do you catch and why those?
Тек шекарадағы операциялық: FileNotFound, IOException, UnauthorizedAccess, JsonException, native үшін DllNotFound, BadImageFormat, EntryPointNotFound. when сүзгісі бағдарламашы қателерін өткізеді: олар қатты құлауы тиіс.
Только операционные, на границах: FileNotFound, DirectoryNotFound, IOException, UnauthorizedAccess, JsonException, а у native — DllNotFound, BadImageFormat, EntryPointNotFound. Фильтр when не пропускает ошибки программиста: они должны падать громко.
Only operational ones, at boundaries: FileNotFound, DirectoryNotFound, IOException, UnauthorizedAccess, JsonException, and for native DllNotFound, BadImageFormat, EntryPointNotFound. The when filter lets programmer errors through: they should fail loudly.
CollectResults неге бірінші қатеде тоқтайды?Почему CollectResults останавливается на первой ошибке?Why does CollectResults stop at the first failure?
«Не бәрі, не ештеңе»: жартылай есеп немесе жоспар адастырады. Бірінші қатеден кейін қалған native шақырулар керек емес.
«Всё или ничего»: частичный отчёт или план вводит в заблуждение. После первого провала остальные native-вызовы не нужны (тест: CollectResults_FirstFailure_IsReturned_AndLaterItemsAreNeverProcessed).
“All or nothing”: a partial report or plan is misleading. After the first failure the other native calls are pointless (test: CollectResults_FirstFailure_...).
C кітапханасын қалай шақырасың және ол жоқ болса не болады?Как вы вызываете C-библиотеку и что если её нет?How do you call the C library and what if it is missing?
NativeMethods-тағы DllImport + SetDllImportResolver; NativeEffortCalculator кірісті тексеріп, DllNotFoundException-ды Failure(NativeLibraryUnavailable) етеді. Қосымша құламай, 4 кодымен шығады.
DllImport в NativeMethods + SetDllImportResolver; NativeEffortCalculator валидирует вход и превращает DllNotFoundException в Failure(NativeLibraryUnavailable). Приложение выходит с кодом 4, а не падает. Тест с реально отсутствующей библиотекой есть в NativeIntegrationTests.
DllImport in NativeMethods + SetDllImportResolver; NativeEffortCalculator validates input and turns DllNotFoundException into Failure(NativeLibraryUnavailable). The app exits with code 4 instead of crashing. NativeIntegrationTests has a test with a really missing library.
Экспорт ескі файлды қалай бұзбайды?Как экспорт не портит старый файл?How does export avoid damaging the old file?
<path>.tmp файлына жазып, File.Move(..., overwrite: true) жасаймыз. Жазу қатесінде tmp жойылады, нысана қозғалмайды.
Пишем в <path>.tmp, затем File.Move(..., overwrite: true). Сбой при записи → tmp удаляется, цель не тронута (тесты Export_Failure_LeavesTheExistingFileUnchanged...).
We write to <path>.tmp then File.Move(..., overwrite: true). A write failure removes the tmp and leaves the target untouched (tests Export_Failure_LeavesTheExistingFileUnchanged...).
